2. Technology Stack & Libraries

Frontend (Client)

  • Vanilla HTML5, CSS3, JavaScript

    How: The entire interface is built as a Single Page Application (SPA) inside a single index.html file without heavy frameworks like React or Angular.

    Why: Ensures instantaneous load times, absolute zero-dependency architecture, and direct manipulation of the DOM and Canvas without framework overhead.

  • HTML5 Canvas API

    How: Used to render the uploaded casting image and draw interactive polygons, circles, and bounding boxes over detected pores.

    Why: It provides native, hardware-accelerated 2D graphics rendering directly in the browser.

  • Custom Computer Vision Engine

    How: The developer wrote custom algorithms (Otsu Thresholding, Morphological closing, PCA) purely in JavaScript.

    Why: Eliminates the need to download massive WebAssembly libraries (like OpenCV.js), keeping the application offline-capable and extremely lightweight.

Backend (Server)

  • FastAPI

    How: Serves the REST API endpoints (/api/porosity/evaluate) that process the frontend's mathematical requests.

    Why: It is currently one of the fastest Python web frameworks available. It auto-generates documentation and seamlessly handles asynchronous requests.

  • Pydantic

    How: Defines strict Python classes (Models) for what a 'Pore' or a 'Spec' should look like. It catches errors if the frontend sends bad data.

    Why: VW50093 is an exact mathematical standard. Pydantic ensures data integrity (e.g., verifying diameters are numbers, not strings) before calculations run.

  • ReportLab

    How: Programmatically draws PDF documents pixel-by-pixel (lines, text, tables) based on the evaluation results.

    Why: It is the industry standard in Python for generating complex, highly customized, print-ready PDF reports.

  • Uvicorn

    How: Runs as the ASGI server executing the FastAPI application.

    Why: It acts as the lightning-fast bridge between the internet (HTTP requests) and the Python code.

3. Step-by-Step Data Pipeline

Step 1: Calibration & Extraction
User traces pores on the frontend Canvas. The Custom JS CV converts these pixel shapes into real-world millimeters using the user's scale calibration.

Step 2: Serialization
The frontend bundles the VW50093 limits (e.g., Max Φ, Max Area %) and an array of every pore's (X, Y, Diameter) into a clean JSON string.

Step 3: Network Transfer
The JSON string is sent via a native JS fetch() POST request to the FastAPI backend.

Step 4: Mathematical Evaluation
The backend calculates complex spatial relationships (like edge-to-edge distance for the "Looseness" H-condition and "Packing" N-condition) using standard Python math.

Step 5: Verdict Generation
The backend returns a new JSON object detailing exactly which checks Passed/Failed. The frontend parses this to update the UI dashboards and indicators.
