2. Technology Stack & Libraries

Frontend (Client)

  • Vanilla HTML5, CSS3, JavaScript

    How: The entire interface is built as a Single Page Application (SPA) inside a single index.html file without heavy frameworks like React or Angular.

    Why: Ensures instantaneous load times, absolute zero-dependency architecture, and direct manipulation of the DOM and Canvas without framework overhead.

  • HTML5 Canvas API

    How: Used to render the uploaded casting image and draw interactive polygons, circles, and bounding boxes over detected pores.

    Why: It provides native, hardware-accelerated 2D graphics rendering directly in the browser.

  • Custom Computer Vision Engine

    How: The developer wrote custom algorithms (Otsu Thresholding, Morphological closing, PCA) purely in JavaScript.

    Why: Eliminates the need to download massive WebAssembly libraries (like OpenCV.js), keeping the application offline-capable and extremely lightweight.

Backend (Server)

  • FastAPI

    How: Serves the REST API endpoints (/api/porosity/evaluate) that process the frontend's mathematical requests.

    Why: It is currently one of the fastest Python web frameworks available. It auto-generates documentation and seamlessly handles asynchronous requests.

  • Pydantic

    How: Defines strict Python classes (Models) for what a 'Pore' or a 'Spec' should look like. It catches errors if the frontend sends bad data.

    Why: VW50093 is an exact mathematical standard. Pydantic ensures data integrity (e.g., verifying diameters are numbers, not strings) before calculations run.

  • ReportLab

    How: Programmatically draws PDF documents pixel-by-pixel (lines, text, tables) based on the evaluation results.

    Why: It is the industry standard in Python for generating complex, highly customized, print-ready PDF reports.

  • Uvicorn

    How: Runs as the ASGI server executing the FastAPI application.

    Why: It acts as the lightning-fast bridge between the internet (HTTP requests) and the Python code.

3. The Computer Vision Pipeline

Step 1: Client-Side Image Processing (Automatic Detection)

Before evaluation, the browser executes a 4-stage CV pipeline using raw pixel data from the Canvas API:

  1. Preprocessing: The image is converted to grayscale to reduce dimensionality. A 3x3 Gaussian filter is applied to remove high-frequency noise/artifacts.
  2. Otsu's Binarization: The algorithm calculates an optimal global threshold by maximizing inter-class variance, separating dark pores from the lighter metal background.
  3. Blob Analysis: A Connected Component Labeling (CCL) algorithm identifies contiguous black pixel clusters. For each cluster, it calculates the Bounding Box, Centroid, and Area.
  4. Geometric Calculation: Using the user-defined calibration (pixels/mm), the engine converts pixel area to mm² and derives the Equivalent Diameter (Φ).

Step 2: Serialization & Transfer

The frontend bundles the VW50093 limits and the detected pores array into a JSON payload sent via fetch() POST to the FastAPI backend.

Step 3: Server-Side Evaluation

The backend calculates spatial relationships (edge-to-edge distances) for "Packing" (N) and "Looseness" (H) conditions across different functional zones.

Step 4: Verdict & PDF Export

The results are rendered onto the UI dashboard. If requested, the ReportLab engine generates a high-resolution PDF with pixel-perfect overlays and a full audit trail.

4. Repository Structure

The project is organized into a clear separation of concerns, ensuring maintainability and scalability.

pvi_web/
├── core/               # Algorithmic Engine (VW50093)
│   ├── calculations.py # Spatial math & grading logic
│   ├── exporter.py     # PDF generation (ReportLab)
│   └── models.py       # Data validation (Pydantic)
├── routers/            # API Endpoints
│   └── porosity.py     # Evaluation & Export routes
├── static/             # Frontend SPA
│   ├── js/             # Canvas CV & Logic
│   ├── css/            # Tailwind styles
│   └── index.html      # UI Entrypoint
├── server.py           # FastAPI Server Entry
├── requirements.txt    # Python dependencies
├── Dockerfile          # Container config
└── render.yaml         # Cloud deployment spec

5. API Specification

Endpoint Method Description
/api/porosity/evaluate POST Validates pore data against VW50093 manufacturing standards.
/api/porosity/export-pdf POST Generates a professional PDF report with overlays and metrics.
/static/index.html GET Serves the main inspection tool interface.

6. Deployment & Production

Local Development

pip install -r requirements.txt
python server.py --port 8000

Docker Production

docker build -t pvi-web .
docker run -p 8000:8000 pvi-web

🚀 Cloud Hosting (Render)

The tool is optimized for Render using the included render.yaml. The backend uses the Python runtime while the frontend is served as static files via FastAPI.
